THEMIS · Project MACH1 alignment · Rev. 2 · October 2026

From a collection of services to a capability platform layer

THEMIS began as 38 named services organized by deployment namespace. Under MACH1, namespaces are packaging and platforms are products. This reference realigns every service into a two-tier capability platform layer: five foundation platforms that govern, measure, and record all AI interaction, and three mission platforms that run the intelligence cycle on top of them. The three accountability axes, Origin, Currency, and Trust, remain the reference architecture spanning the layer.

The carve

Principle

A capability platform must answer three questions: who consumes it besides ATHENA, would it survive if ATHENA were retired, and can one team own its roadmap end to end. Services are placed by durable capability, never by namespace. A platform is existing only when it has running code and a named owner; everything else is a charter. Mission platforms are headless-first: every capability ships as APIs and event streams, and the SuperApp surface is one consumer among several, with agents as first-class consumers.

Foundation tier

Five charters

The platforms every other platform's contracts depend on. Provenance and AIAS take the Oct–Dec build investment; Governance, Trust Calibration, and Content Integrity charter now and build the thin slices January needs against their schemas.

Provenance and custody

Charter · build Oct–DecName available: ARBOR

The evidentiary system of record. Every platform service signs events into it, KAIROS propagation walks its DAG, and every research trail, document attribution, and reasoning record lives in it. Greenfield, but the MOIRAI specification is the most complete in the architecture: signed events, hash chaining, and external timestamp anchoring are build-ready.

Deepest dependency in the layer. The event schema and write API are the first deliverables, because no other platform can emit signed events without a schema to sign against.

Provenance / MOIRAIAI content provenanceOriginal

Signed, hash-chained provenance graph of all AI-touched content. Nodes for session, turn, claim, chunk, document, analyst, model version, and corpus snapshot; edges for produced, retrieved, verified, derived from, attributed to, and superseded by. Multi-analyst attribution per session and a matter-level cross-session query index.

Spec detail
Write path
Validates the cryptographic signature and the prev_event_hash against the actual prior event before accepting; mismatch rejects. All platform services and infrastructure sign via Vault before submission.
Anchoring
24-hour chain digest to an external RFC 3161 timestamp authority.
Fallback
Unavailability never stops sessions: producers buffer to Kafka, MOIRAI replays on recovery, and affected sessions carry a buffered flag in the manifest.
DPS / CODEXDocument provenanceAddendum A

Paragraph-level attribution of AI contribution in finished intelligence, with bidirectional integration into the authoring environment.

Spec detail
Lifecycle events
AI content insertion carries a full provenance payload with AEGIS scope validation; content edits compute an edit depth score (embedding distance from AI draft to human revision) routed to ALETHEIA; document open triggers a KAIROS currency check across every source in the provenance map.
Write path
Batched, signed document events through a Kafka write buffer.
ERAS / LOGOSReasoning auditOriginal

Per-turn structured reasoning records: claims, reasoning chain, unsupported claims, and confidence signals, captured asynchronously so response display never blocks. The audit artifact for oversight disclosure, structured as ICD 203 analytic standards documentation.

Spec detail
Unsupported claims
Flags assertions no retrieved evidence in the turn's context supports, cross-referenced against the HERMES retrieval trace; the highest-priority signal routed to MIMIR calibration and ALETHEIA.
Storage
Elasticsearch claim index; signed capture events published through Kafka into MOIRAI.

AIAS

Charter · build Oct–DecEnforcement point (PEP)

The AI orchestration layer in the MACH1 target structure, and the data path every interaction crosses. The charter is partly formalization and partly build: the MCP runtime runs today and gets wrapped behind one platform contract; the gateway, retrieval, and agent services are new. AIAS hosts the enforcement points that evaluate AI Governance decisions.

January thin slice: the running runtime behind one contract, with the governance hook live at the gateway. Retrieval and SAGA sequence after.

MCP runtimeTyk gateway · Lumbra orchestration · MCP registryRunning today

The operational MCP plumbing: Tyk as the gateway, Lumbra for orchestration, and the custom-built registry of record for tools. The charter productizes them with an owner, SLOs, and a roadmap, and mounts the MGS policy evaluation hook at the Tyk gateway.

Inference GatewayModel inference routingBuild

Single path for all model inference: routing across vendors, prompt assembly and injection, context capture for downstream audit, and enforcement of KRONOS version pins at the gateway rather than in applications.

RetrievalCorpus search and chunk retrievalBuild · rename from MIMIR Retrieval

Vector store and retrieval service returning chunks with match scores, instrumented end to end by HERMES. Renamed in this alignment to clear the collision with the MIMIR calibration service, which keeps the epithet.

MOS / SAGAMemory orchestrationAddendum C

Owns the logic of what memory means; MOIRAI owns the record. Agent task memory as Redis task state with milestone promotion into MOIRAI, version chains for revisable session summaries, and supervisor routing when analysts produce contradicting graduated claims.

Spec detail
Handoff validation
On handoff, SAGA validates the receiving analyst holds access to all evidence referenced in task state, including completed sub-tasks; any out-of-scope evidence blocks the handoff until resolved.
Tier inheritance
Every memory artifact inherits the most restrictive protective tier of any contributing evidence, computed at creation from AEGIS records and enforced by AEGIS at retrieval; tier changes propagate to derived artifacts.
Traceability
MOIRAI reverse DAG traversal reaches memory artifacts through derivation edges SAGA writes at creation.
Capability boundingAgent session envelopesAgent-native

Enforces the capability envelope a session was granted: a bounded agent cannot acquire tools, scopes, or corpora beyond its grant mid-task. The runtime enforcement side of the grants PRS, SKS, and MGS govern.

Coalition handlingMulti-agent coordinationAgent-native

Shared task state and per-agent attribution for agent coalitions, with compartment checks on every inter-agent exchange so a coalition can never launder content across a boundary its members hold separately.

AI governance

Charter · keeps the THEMIS nameDecision point (PDP)

The policy decision platform for all AI interaction: compartment enforcement, interaction class policy, adversarial screening, and governance of the prompts, skills, and tools the runtime may load. Structurally independent of AIAS so the referee never reports to a player; decisions are served through Cerbos-pattern decision APIs and evaluated at AIAS enforcement points.

January visible value: the gates. No AI interaction touches intelligence without compartment clearance and policy guardrails.

PCES / AEGISCompartment and classification enforcementOriginal

First in every request path, before policy, retrieval, or inference, with no fallback: failure is a hard stop. Requirement scope is a hard boundary, so source intelligence from one requirement cannot appear in a session scoped to another, and conflict-of-interest detection runs against the cleared-personnel registry at session open.

Spec detail
Schema
UNCLASSIFIED through TS_SCI and SAP, with handling caveat enforcement.
Latency
P99 under 50ms in the synchronous critical path; cache-first requirement scope in Redis, cold lookup from PostgreSQL only on miss or session boundary.
Record
Append-only, signed classification log of every compartment decision; immutable consent and collection-authority records.
PGS / NOMOSPolicy and guardrailsOriginal

Second in every path, after compartment clearance, failing safe to the most restrictive policy. Interaction classes (intelligence analysis, finished intelligence, research, debriefing prep, expert briefing) each carry configurable constraints: VERITAS mode, dissemination gate thresholds, counter-position requirements, and hardening eligibility.

Spec detail
Rule engine
YAML rules in a version-controlled policy store; changes are PRed, reviewed by the Intelligence Oversight Board, and deployed through formal change control. Policy-as-code, the same pattern as the Cerbos authorization layer.
Auditability
The policy version is logged into every session manifest and provenance record, enabling policy-stratified audit queries.
Latency
P99 under 100ms; in-memory evaluation against the cached rule set.
IAS / SCUDOAdversarial input screeningAddendum A

Screens at retrieval ingestion, before chunks enter the candidate pool, because corpus poisoning and prompt injection through fabricated open-source reporting are active denial-and-deception techniques. Clean chunks flow in parallel; only quarantine dispositions block synchronously.

Spec detail
Detection layers
Signature matching against the injection taxonomy (Red Team maintained, reviewed quarterly by the oversight board); embedding similarity against the adversarial pattern corpus; heuristic scoring of imperative-directive patterns such as role reassignment and system prompt override attempts.
PRSPrompt registryInteraction layer

Prompts as governed artifacts: versioned, signed, and bound to interaction classes, so the runtime loads only registered prompts and every session manifest records which version ran.

SKSSkill governanceInteraction layer

Registration, review, and scope grants for skills before the runtime may load them, with the same version-controlled change discipline as NOMOS policy.

MGSMCP tool governanceInteraction layer

Policy over the MCP runtime AIAS operates: which tools exist in the registry, who may grant them, and what scopes a session may hold. Decisions are evaluated at the Tyk gateway hook; the hook contract is a published platform API, the PDP/PEP interface between this platform and AIAS.

Trust calibration

Charter · flagshipDissertation core

The measurement plane for the human-AI reliance relationship: continuous calibration of analyst trust against measured model accuracy, per domain and per modality. The one genuinely novel platform in the portfolio, consumable by any AI surface in the organization, with service contracts the dissertation instrument depends on.

TCS / MIMIRTrust calibrationOriginal

Domain-specific Bayesian posterior per claim type, domain, model version, and source type, initialized from vendor benchmarks at cold start and updated from weighted ALETHEIA corrections. Separate calibration streams per modality, since calibration on documents does not transfer to video.

Spec detail
RAI engine
Seven behavioral input streams combined into a Reliance-Accuracy Index per analyst per domain: verification completion, episode follow-through, reformulation quality, counter-position engagement, inverted gaming probability, pressure mode adjustment, and supervisory confirmation.
Fallback
On unavailability, surfaces display conservative prior badges rather than model self-report; the degraded state is visible in the session manifest.
Latency
Score serving from Redis P95 under 50ms; calibration updates batch every 15 minutes from the correction stream.
FGTS / ALETHEIAFeedback and ground truthOriginal

The proprietary ground truth corpus built from analyst verification outcomes, with five-factor correction weighting: domain RAI, inverted gaming score, pressure multiplier, supervisory confirmation, and peer agreement. The asset no external vendor can replicate.

Spec detail
Review queue
Three triggers: weight below threshold, contradiction of a prior high-confidence correction, and a high-confidence badge marked incorrect, the highest-consequence correction type. Accept, reject, or escalate by the corpus quality specialist.
Versioning
Weekly corpus snapshots stored as signed MOIRAI events; rollback selects a prior snapshot and recomputes calibration, tractable because the corpus uses weighted accumulation rather than gradient descent.
UCS / TYCHEUncertainty decompositionAddendum F core

Decomposes uncertainty rather than flattening it into one score: what is assessed, what kind of uncertainty attaches to it, and what would change it. Carries the explicit temporal profile CHRONOS projections require (horizon length, whether the subject has decided or the trajectory is constrained, assumption sensitivity) and produces the three-sentence confidence translation IRIS delivers to policymakers.

OFS / NEMESISOutcome feedbackAddendum F core

Records what actually happened against the claims and assessments that preceded it, closing the accuracy loop calibration depends on. Supplies trajectory validation data to CHRONOS and outcome ground truth to ORACLE, with forecast outcomes and current-state outcomes measured as the different things they are.

MDS / KRONOSModel driftAddendum A

Polls vendor version endpoints every four hours and fires a version change event within four hours of any release. Queries MOIRAI for all active matters that used the prior version in the trailing window and flags their calibration baselines as potentially stale pending review, never silently reset.

Spec detail
Version pinning
Pinned matters route all inference to the pinned version, enforced at the Inference Gateway rather than in applications; pin release on active requirements requires oversight board acknowledgment.
CPS · ODSCapability profiling · Out-of-distribution screeningProposed · Addendum D

The proposed competence axis: profiling what each model is measurably good at, and screening whether a query sits inside the model's competence envelope before confident output reaches an analyst. Partially buildable now; hard enforcement is gated on six open research questions, so both carry proposed status in this charter.

Content integrity

CharterJanuary-visible value

Continuous assurance that content entering, produced by, or persisting in analysis is corroborated, current, authentic, and faithfully retrieved. Trust Calibration measures the reliance relationship; this platform measures the content itself, at five points in its lifecycle. Its signature capability is the sensing loop: ARGUS detects external change, KAIROS decides and propagates, and the blast radius lands in the corpus, open documents, and the badge layer without human triage.

CVS / VERITASSource corroborationAddendum A

Fires on every model response before rendering, checking citations against the IC intelligence databases, with a hard interrupt on no corroboration. The direct counter to fabricated source reporting, the most acute failure mode in AI-assisted analysis.

Spec detail
Mode
Configured per NOMOS interaction class: mandatory-blocking for intelligence analysis and finished intelligence, advisory for research classes. Blocking mode holds the response until resolution completes or the interrupt fires.
Latency
P95 under 2 seconds for responses carrying up to 10 citations; no-corroboration interrupts are synchronous and immediate.
TVS / KAIROSTemporal validityOriginal

Validity as a continuous quantity: configurable decay functions per document type, with foundational assessments decaying slowly, current intelligence at medium half-life, tactical reporting fast, and debriefings by source reliability rating. Supports point-in-time reconstruction of what a source's validity was when the analyst relied on it.

Spec detail
Propagation
On an active invalidation from ARGUS, walks the MOIRAI provenance DAG to every derived claim and emits validity change events, asynchronously over seconds to minutes depending on DAG depth.
Corpus extension
ALETHEIA corpus items register alongside active evidence; invalidation of an underlying source fires a corpus decay event routing the item to human review, on a longer half-life profile than live evidence.
Fallback
Cached validity with an explicit staleness warning; document provenance panels flag validity as unavailable.
RQS / HERMESRetrieval qualityOriginal

Observability over the AIAS retrieval pipeline, with no analyst-facing surface of its own: rolling precision per query class, domain, and corpus version computed from ALETHEIA verification outcomes, and miss detection that cross-references "not in sources" corrections with retrieval traces to isolate synthesis confabulation.

Spec detail
Validity intersection
Flags queries where low-validity sources were retrieved and used, a quality failure independent of whether the model characterized the source correctly.
Contract
Requires read access to AIAS retrieval traces, the cross-platform contract to negotiate early.
KCS / ARGUSExternal currencyOriginal

The sensor: monitors OSINT aggregators, allied reporting, foreign open media, collection status, and academic feeds for developments that supersede or compromise sources, and emits active invalidation requests to KAIROS.

Spec detail
Watch lists
Each active requirement registers entities of interest; watched entities are prioritized above general feed monitoring. Polling hourly to every six hours by feed type and priority class, credentials through Vault.
Confidence scoring
Low-confidence invalidation events surface as advisories rather than triggering immediate propagation.
MAS / EIDOLONMedia authenticityAddendum A

Ensemble classifiers at media ingestion, before any AI analysis begins: video (facial inconsistency, temporal artifacts, compression patterns, metadata), audio (voice synthesis, speaker verification, acoustic continuity, spectral anomaly), image, and OCR. Risk scores attach to the provenance record and set confidence ceilings downstream; only quarantine dispositions block analysis.

Mission tier

Three charters · headless-first · Year 2+ build

Domain capability platforms running the intelligence cycle on the foundation tier, reimplementing none of it. Each capability ships as APIs and event streams first; SuperApp surfaces and agents consume them on equal terms. Chartering now fixes the map; the build sequence stays Year 2 and beyond.

Operational research

Charter · candidate name: STOA, elevated

Orchestrated analysis as a service, on operational tempo: a question and constraints in, a badged and trailed decision-grade product out. Pattern analytics, comparable-matter intelligence, and anticipation are modes of the same engine, which is why they share one platform and one team.

Elevating STOA to the platform name means re-epitheting the session service.

STOAResearch orchestrationthemis-research

Structures research as documented multi-step workflows where a single RAG call retrieves and synthesizes: query decomposition, iterative refinement, sub-question routing, source triangulation, and synthesis, with a complete trail from initial question to final answer. LOGOS captures the reasoning; STOA captures the methodology, and the trail is a first-class MOIRAI provenance artifact. ARGUS is consulted before synthesis is delivered, so retrieved authority affected by external developments never ships unflagged.

ORACLEOutcome analyticsthemis-research

Predictive intelligence from the organization's own historical outcomes, where every pattern is transparent, attributable, and traceable to specific matters rather than a black-box score: three prior requirements with this target type were assessed within 45 days at 70 percent confidence accuracy is the shape of what it produces. Requires 200+ historical matters for significance; ALETHEIA correction patterns reveal which predictions analysts trusted versus overrode, and MIMIR flags systematic over- or under-weighting.

MIRRORSimilar matter intelligencethemis-research

Finds the most similar historical matters for any active requirement across six weighted dimensions: collection approach, target domain, adversary profile, geopolitical context, source pattern, and geography. Comparables arrive outcome-linked, with complication patterns that arose in similar matters surfaced before they recur, and analyst experience matching for informed staffing. Similarity refreshes continuously as the requirement evolves; 50+ matter floor, with KAIROS validity weighting comparable quality.

PYTHIAAnticipatory intelligencethemis-research

Surfaces the research and evidence a team will need before they know to ask, modeled on the matter's lifecycle stage from MIRROR's similar set and MNEMOSYNE's knowledge of how those matters developed. Pre-executes likely research through STOA so results are ready at need, surfaces deadlines with the lead time comparable matters suggest, and produces the matter intelligence brief, the unified surface through which the mission tier speaks to the analyst. The most downstream service in the architecture.

Indications and warning

Charter · candidate name: PHAROS

Continuous sensing over the knowledge and provenance base, emitting warning event streams anything can subscribe to. The architecture's answer to unknown unknowns: it does not eliminate them, it converts more of them into known unknowns faster than an ungoverned platform would. Supervisory-facing first, because several services necessarily operate across requirement compartments and every boundary crossing is an AEGIS decision.

TRS / CHRONOSTemporal reasoningthemis-warning

Forecasting as a distinct analytical mode, epistemically separate from current-state assessment: a 30 percent event occurring is not a failed forecast, while a missed existing capability is a failed assessment. Trajectory models as time-indexed probability distributions labeled as projections, leading indicator monitoring with historical confirmation rates, and scenario space generation with discriminating indicators, all routed through TYCHE's temporal uncertainty profile before any analyst or policymaker sees them.

ADS / CASSANDRAAnomaly detectionthemis-warning

Treats deviation from known pattern as intelligence rather than noise: if an adversary program typically generates signature X at development stage Y, and stage Y shows no signature X, that absence surfaces as an analytical signal. Built on ORACLE behavioral baselines and the MNEMOSYNE signature corpus; advisory-only until false positive rates are characterized.

CGS / ARGUS-LACUNACollection gap mappingthemis-warning

Maps collection coverage per requirement and distinguishes two critically different silences: absence of evidence, where collection is pointed at the target and finding nothing, versus absence of collection, where nothing is pointed there at all. Surfaces a gap indicator on parametric claims in uncollected domains, so an analyst knows whether the AI's silence reflects the target or the platform's blindness.

WSF / LACHESISWeak signal fusionthemis-warning

Surfaces signal clusters across active requirements that exceed significance thresholds their individual components never reach, the classic failure pattern of dots nobody connected because connecting was nobody's job. Every compartment-crossing signal is gated by AEGIS; supervisory-facing only until crossing policy is formally established. Needs roughly 30 simultaneous active requirements before clusters outrun noise.

CRF / JANUSCross-requirement correlationthemis-warning

Surfaces the existence of semantic correlations across requirements worked separately: entity overlap through YGGDRASIL resolution, timeline correlation, source overlap, and converging conclusions. Never reveals content across boundaries; it routes the correlation to an analyst or supervisor who holds access to both sides, with AEGIS authoritative in all phases.

SWS / SENTINELStrategic warningthemis-warning

Watches for signatures of strategic surprise, developments with no direct precedent that would fundamentally change the analytical picture, by fusing CASSANDRA anomalies, LACHESIS clusters, ORACLE deviations, and MNEMOSYNE near-miss knowledge against a strategic indicator registry. Architecturally last, and honestly so: whether surprise signatures can be specified without knowing the surprise is the hardest open design question in the tier.

Tasking and dissemination

Charter · candidate name: KYKLOS

The intelligence cycle's bookends as APIs, owning the external integration surface where the cycle touches the outside world: requirements systems upstream, decision-makers downstream. Two services is thin for a platform; the integration contracts are what earn the charter.

TIS / DIKETasking integrationAddendum F · themis-requirements

Closes the loop into requirements management: when ARGUS-LACUNA identifies a collection gap, DIKE generates a collection gap request for requirements officers carrying the uncovered domain, the estimated uncertainty reduction from TYCHE, and a suggested approach from ORACLE outcome data. Returns collection effectiveness upstream and tracks the full requirement lifecycle from tasking through outcome. The API agreements with requirements systems make the RM boundary a platform contract.

PCS / IRISPolicymaker communicationAddendum F · themis-dissemination

Translates provenance and calibration metadata into consumer packages for decision-makers: plain-language source basis, the three-sentence confidence translation from TYCHE (what is assessed, what kind of uncertainty, what would change it), key assumptions, falsification indicators, the prior outcome record, and a cryptographic provenance certificate from the custody platform.

Knowledge substrate

One existing platform · absorbs themis-knowledge

TESSERA is the one platform in this alignment whose scope exceeds THEMIS: it is the knowledge substrate of the entire Intelligence OS, and it absorbs the themis-knowledge services as its semantic layer. It is the only component to pass the existence test, which makes it the anchor of the migration story: eight charters build around a substrate that already runs.

TESSERA

Existing · confirmedIntelligence OS substrate

The governed knowledge base every platform reads from and writes to: the intelligence corpora retrieval runs over, the canonical semantics agentic services reason with, and the institutional knowledge the mission tier compounds into. The boundary lines are deliberate. TESSERA owns what is stored and what it means; AIAS owns how it is searched; Provenance and Custody owns what happened to it; HERMES measures the seam between them. Every mission platform rests on this foundation: without a governed ontology, agentic services reason confidently about relationships that are semantically incoherent.

The flywheel lives here. Every matter adds corrections, comparables, outcomes, and institutional knowledge to the substrate, an accumulating advantage built on the organization's own data that no external vendor can replicate.

Corpus managementGoverned intelligence corporaSubstrate

The document and knowledge stores the AIAS retrieval service searches: ingestion, indexing, and versioned corpus snapshots registered as first-class nodes in the provenance graph, so HERMES can track retrieval precision per corpus version and staleness questions have an authoritative answer. Compartment and classification labels attach at ingestion, giving AEGIS scoped retrieval something to enforce against.

OGS / YGGDRASILOntology governancethemis-knowledge

The machine-readable, version-controlled canonical entity model for the intelligence domain: entity types, properties, and valid relationships, with cross-INT resolution so target, actor, and entity of interest resolve to one concept across SIGINT, HUMINT, and IMINT reporting. Built on existing IC standards (STIX for threat entities, NSG for geospatial, agency taxonomies) with a governance mechanism for extensions rather than a new ontology from scratch. The semantic grounding prerequisite for the entire mission tier.

MNEMOSYNEInstitutional memorythemis-knowledge

Captures and makes queryable the tacit institutional knowledge that otherwise walks out the door: a synthesis layer aggregating ALETHEIA correction patterns, ORACLE outcomes, MIRROR similarity, and STOA research trails into a structured knowledge graph, surfaced when relevant without the analyst needing to know it exists. Aggregates rather than generates; cannot be built until the corpus matures and ORACLE and MIRROR are operational.

SCRIBESemantic versioningthemis-knowledge

Semantic diff over document versions: reads the MOIRAI graph to attribute AI-contributed content per version and writes version diff records back as edges between document nodes. KAIROS validity informs the classifier, so a clause change resting on a low-validity source is flagged differently from an ordinary edit.

Standing decisions

Cross-cutting

The existence test

A platform is existing only with running code and a named owner. By this test, ARBOR and AIAS moved from the existing column to charters; TESSERA passed, and is the alignment's one existing platform.

PDP / PEP split

Governance owns policy decisions; AIAS owns enforcement points. The hook contract at the Tyk gateway is a published platform API, the Cerbos pattern extended from authorization to interaction policy. Teams may merge for capacity; the platforms never do.

The MIMIR rename

The calibration service keeps the epithet; the retrieval service in AIAS is renamed during migration. Two services sharing a name across two platforms with two owners is an operational hazard.

Schema before services

The provenance event schema and write API ship first. Every other platform's contracts sign against them, so nothing else's interface is final until they exist.

Oct–Dec scope

Charter all eight on paper now; build only what January needs: the provenance write path, the AIAS runtime behind one contract with the governance hook live, and the visible slices, gates and badges, on top.

Headless-first mission tier

Mission capabilities ship as APIs and event streams; SuperApp surfaces are one consumer among several, and agents are first-class consumers from the first contract.
